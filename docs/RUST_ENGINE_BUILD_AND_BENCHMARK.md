# Rust engine build and browser benchmark

This runbook is the executable delivery contract for phases R0-R2 of the hybrid engine migration. It packages `blockwild-wasm` without hiding tool installation, publishes immutable content-addressed files, rejects stale or modified artifacts, and records browser bootstrap and Worker-transfer costs as JSON.

## What the tooling owns

- Rust workspace: `engine/Cargo.toml`
- Browser crate: `engine/crates/blockwild-wasm` (`blockwild-wasm`)
- Build staging: `work/rust-engine-build/` (ignored, build-owned)
- Published browser index: `public/engine/manifest.json`
- Published immutable artifact: `public/engine/<64-character-sha256>/`
- Suggested measurements: `work/hybrid-rust-migration/browser-benchmarks/`

The scripts never install Rust targets, Cargo packages, browsers, or Node packages. They do not change `HOME`, `USERPROFILE`, or a Cargo home. Every subprocess is synchronous except the explicitly managed browser, and the browser and local HTTP server are closed in `finally` blocks.

## One-time local prerequisites

The repository's `rust-toolchain.toml` is authoritative. The build refuses a floating `stable`/`nightly` channel and refuses `rustc` that differs from the exact pinned release.

Install prerequisites deliberately outside the build script:

```powershell
rustup target add wasm32-unknown-unknown
```

Install a `wasm-bindgen` CLI whose version exactly matches the `wasm-bindgen` package in `engine/Cargo.lock`. Confirm both before building:

```powershell
wasm-bindgen --version
Select-String -Path engine\Cargo.lock -Pattern 'name = "wasm-bindgen"' -Context 0,1
```

`wasm-opt` is optional. It is used only when its executable is explicitly supplied with `--wasm-opt` or `BLOCKWILD_WASM_OPT`; ordinary development builds do not depend on it.

## Reproducible browser build

From the repository root:

```powershell
node scripts/build-rust-engine.mjs --package blockwild-wasm --variant compatibility
```

The builder performs these steps:

1. discovers `engine/Cargo.toml` through locked Cargo metadata;
2. verifies the exact pinned Rust release and installed `wasm32-unknown-unknown` target;
3. verifies that the local `wasm-bindgen` CLI exactly matches `engine/Cargo.lock`;
4. runs a locked Cargo build for the selected package/profile/features;
5. generates browser `web` glue in a build-owned staging directory;
6. optionally optimizes the final Wasm binary with an explicitly supplied local `wasm-opt`;
7. hashes every generated file path, SHA-256, and byte length;
8. publishes the package at `public/engine/<hash>/` and atomically updates the index;
9. removes only unreferenced directories strictly inside `public/engine/`;
10. re-reads all bytes and verifies the complete published package before succeeding.

Useful explicit variants:

```powershell
node scripts/build-rust-engine.mjs --package blockwild-wasm --variant compatibility
node scripts/build-rust-engine.mjs --package blockwild-wasm --variant renderer-lab --features renderer
node scripts/build-rust-engine.mjs --package blockwild-wasm --variant accelerated --features wasm-simd
node scripts/build-rust-engine.mjs --package blockwild-wasm --variant speed-lab --profile release --wasm-opt C:\Tools\binaryen\bin\wasm-opt.exe
```

Only use a feature after that feature exists in the crate. The script forwards feature names but never invents or enables accelerated behavior implicitly.

The compatibility artifact intentionally contains only the authoritative engine facade. The `renderer-lab` artifact is separately loaded by diagnostics because `wgpu` increases its current raw Wasm payload by roughly an order of magnitude. Keeping these modules split proves the renderer without charging every supported browser the renderer-lab download during the strangler phases.

### Published manifests

`public/engine/manifest.json` is the small mutable selector. It records the default variant and maps each variant to a content hash and nested manifest. Each `public/engine/<hash>/manifest.json` records:

- Rust package and package version;
- protocol/schema version;
- exact Rust, Cargo, `wasm-bindgen`, and optional `wasm-opt` versions;
- target, Cargo profile, and sorted feature list;
- file roles, MIME types, raw sizes, and SHA-256 checksums;
- total raw, gzip, and Brotli bytes.

The nested manifest is metadata and is not part of its own content hash. Generated JavaScript, Wasm, type declarations, and support files are. A repeat build with identical generated bytes reuses the same directory.

## Artifact verification

Verify the checked-out files:

```powershell
node scripts/check-rust-engine-artifacts.mjs
```

The check fails on:

- a missing or unsupported manifest;
- a directory that is not named by its SHA-256 content address;
- a missing, modified, or unmanifested file;
- an unreferenced stale artifact directory;
- missing JavaScript glue or Wasm;
- role or MIME metadata drift.

Verify bytes and MIME types from a running site:

```powershell
node scripts/check-rust-engine-artifacts.mjs --base-url http://127.0.0.1:3000
```

For a production/CDN gate, additionally require immutable caching on hashed files:

```powershell
node scripts/check-rust-engine-artifacts.mjs --base-url https://blockwild.app --strict-http
```

The index itself remains mutable; only content-addressed files require a long-lived immutable cache policy.

## Browser bootstrap and transfer benchmark

The browser harness measures the exact published hash, not a Cargo target file:

- no-store Wasm fetch latency and served MIME type;
- `WebAssembly.compile` latency;
- fresh `wasm-bindgen` glue import plus instance initialization latency;
- zero-argument `blockwild_protocol_version()` heartbeat latency;
- transferable `ArrayBuffer` Worker round trips at 64 KiB, 1 MiB, and 4 MiB by default;
- browser/user-agent, CPU-count, memory hint, cross-origin isolation, and streaming capability;
- console/page errors (any error fails the run).

Record a local measurement:

```powershell
node scripts/benchmark-rust-browser.mjs `
  --variant compatibility `
  --runs 15 `
  --transfer-runs 30 `
  --output work/hybrid-rust-migration/browser-benchmarks/compatibility.json
```

If Playwright is not a project dependency, point at an already installed local ESM entry without downloading anything:

```powershell
$env:BLOCKWILD_PLAYWRIGHT_MODULE = 'C:\path\to\node_modules\playwright\index.mjs'
node scripts/benchmark-rust-browser.mjs --output work/hybrid-rust-migration/browser-benchmarks/compatibility.json
```

The script also recognizes the Playwright bundled with the local Codex `develop-web-game` skill when present. Chrome or Edge is discovered from standard install paths on Windows; use `--browser-executable` for another local browser. The harness starts a loopback-only static server when `--base-url` is omitted, and always closes that server and the launched browser before returning.

Measure an already running deployment by passing its base URL:

```powershell
node scripts/benchmark-rust-browser.mjs `
  --base-url https://blockwild.app `
  --variant compatibility `
  --output work/hybrid-rust-migration/browser-benchmarks/production.json
```

Use `--heartbeat-export` only for a deliberate ABI experiment. The production default is the shipping `blockwild_protocol_version` export. Transfer sizes are comma-separated bytes, for example `--transfer-sizes 65536,262144,1048576`.

## Interpreting results

Every timing family contains count, mean, p50, p95, p99, minimum, and maximum. Retain the complete JSON with its artifact hash. Do not compare a native Cargo benchmark with a browser frame benchmark as if they were the same workload. For migration decisions:

- compare identical artifact variants and browser versions;
- interleave TypeScript/Rust A/B/A runs when measuring end-to-end play;
- keep fetch, compile, instantiate, heartbeat, transfer, engine-step, render, and input-to-visible latency separate;
- reject any phase that breaches the plan's scenario floor even if a kernel microbenchmark improves;
- treat cold-start and transferred-byte growth as first-class costs.

## Failure recovery

- **No workspace:** wait for or restore `engine/Cargo.toml`; the builder does not scaffold it.
- **Missing target:** install `wasm32-unknown-unknown` explicitly with `rustup`, then rerun.
- **Binding version mismatch:** install the exact lockfile version; never bypass the check.
- **`.build-lock` exists:** verify the recorded PID is gone before removing the stale file. Never delete it while another build is active.
- **Checksum/stale-file failure:** do not hand-edit `public/engine`. Rebuild from the locked Rust source.
- **Browser launch failure:** pass an existing Playwright module and browser executable; the harness never downloads either.
- **Heartbeat missing:** preserve the versioned zero-argument `blockwild_protocol_version` export or pass an explicitly reviewed replacement.

These tools establish packaging and measurement. They do not by themselves promote Rust authority or the `wgpu` renderer; those remain separate, measured selectors under the migration authority ledger.
